Fase 1: Fundamentos (HTML, CSS, HTTP & Cliente-Servidor)

Arquitetura Cliente-Servidor

O Cliente (browser) inicia a comunicação enviando pedidos HTTP e renderiza HTML/CSS/JS. O Servidor (Express/Node.js) escuta os pedidos, faz lógica de negócio, acede à BD e devolve respostas. Garante a ocultação de credenciais.

Métodos HTTP vs CRUD

Sai sempre em exames: CREATE e UPDATE não são verbos HTTP! São operações CRUD. O mapeamento correto é:

Operação CRUD Método HTTP Idempotente? Exemplo de Rota
Create POST Não (cada chamada cria um novo recurso) POST /api/products
Read GET Sim (apenas lê dados, não altera estado) GET /api/products
Update PUT / PATCH Sim (PUT substitui o recurso por completo) PUT /api/products/:id
Delete DELETE Sim (remover o mesmo ID duas vezes dá o mesmo estado final) DELETE /api/products/:id

3 Formas de incluir CSS

  • Inline: <p style="color: red;"> (Não recomendado, mistura estrutura e apresentação).
  • Internal: Tag <style> dentro do <head> (Aplicado apenas a uma página).
  • External: Tag <link rel="stylesheet" href="..."> (Recomendado: cache do browser, reutilização, organização).
Fase 2: JavaScript DOM, AJAX & Web Storage

Seleção de Elementos DOM

  • document.getElementById(id): Retorna o primeiro elemento com o ID indicado. IDs devem ser únicos.
  • document.getElementsByClassName(classe): Retorna uma HTMLCollection (coleção de elementos).
  • document.querySelector(seletorCSS): Retorna o primeiro elemento correspondente ao seletor CSS.
  • document.querySelectorAll(seletorCSS): Retorna uma NodeList com todos os elementos correspondentes.

Persistência no Browser: Local vs Session Storage

  • localStorage: Permanente. Os dados continuam gravados mesmo depois de fechar e reabrir o browser/computador. Limite de ~5-10MB. Guarda apenas strings.
  • sessionStorage: Temporário. Os dados são apagados assim que a aba ou sessão do browser é fechada.
// Guardar objeto
localStorage.setItem("user", JSON.stringify(userObj));
// Ler objeto
const user = JSON.parse(localStorage.getItem("user")) || {};
Fase 3: ExpressJS, MVC & Mongoose (Backend)

Express Middleware

Funções executadas no ciclo de pedido-resposta. Devem chamar next() para passar o controlo para o seguinte middleware. O middleware de erros tem obrigatoriamente 4 parâmetros:

app.use(function(err, req, res, next) {
  console.error(err.stack);
  res.status(500).send('Ocorreu um erro no servidor!');
});

Mapeamento MVC no Express

  • Model: Schemas e modelos Mongoose (ex: models/product.js).
  • View: Templates EJS com dados dinâmicos compilados no servidor (Server-Side Rendering) (ex: views/index.ejs).
  • Controller: Funções que recebem o pedido HTTP, chamam o Mongoose e renderizam o template (ex: controllers/productController.js).
Fase 4: Angular, Componentes, Serviços & Comunicação

4 Tipos de Data Binding

  • Interpolação: {{ propriedade }} (Direção: Componente para HTML / String).
  • Property Binding: [propriedade]="expressao" (Direção: Componente para HTML / Atributo).
  • Event Binding: (evento)="metodo()" (Direção: HTML para Componente).
  • Two-Way Data Binding: [(ngModel)]="propriedade" (Direção: Bidirecional. Requer import do FormsModule).

Serviços Angular

Classes decoradas com @Injectable({ providedIn: 'root' }). São singletons, não têm qualquer template HTML associado e servem para encapsular lógica e chamadas à API REST.

Guards vs Interceptors

Propriedade Guard (Guarda de Rota) Interceptor (Interceptador HTTP)
Interface CanActivate / CanActivateChild HttpInterceptor
Onde atua Antes de carregar uma página (routing) Antes de enviar um pedido HTTP ao servidor
Objetivo Principal Bloquear acesso de utilizadores sem sessão Anexar o token JWT ao header de cada pedido

Parte 2 — Verdadeiro ou Falso (2 valores)

Afirmação 2.1 0.5 valores
“Server-Side Rendering (SSR) é o nome da técnica utilizada durante o semestre para desenvolvimento de componentes em angular.”
FALSO

Correção: O Angular é tipicamente utilizado para **Client-Side Rendering (CSR)** no modelo de **Single Page Application (SPA)**, onde os componentes são construídos e renderizados dinamicamente pelo browser (cliente). O SSR é usado por exemplo no backend com Express e EJS.

Afirmação 2.2 0.5 valores
“Uma aplicação desenvolvida exclusivamente em Angular é uma aplicação fullstack.”
FALSO

Correção: O Angular é uma framework exclusivamente frontend (corre no browser). Para ser uma aplicação fullstack precisa da camada de backend (ex: Express/Node.js) e de base de dados (ex: MongoDB).

Afirmação 2.3 0.5 valores
“Numa aplicação web é possível fazer o deploy do frontend e backend em servidores separados.”
VERDADEIRO

Justificação: É uma prática comum. O frontend (ficheiros estáticos gerados na build do Angular) é hospedado em serviços de conteúdo estático (como CDN, Netlify ou Vercel), e o backend (a API REST em Express) é executado num servidor aplicacional (como VPS ou Render). Comunicam via pedidos HTTP/HTTPS assíncronos (requer configuração de CORS).

Afirmação 2.4 0.5 valores
“O CSS é uma linguagem de programação utilizada para formatar páginas html.”
FALSO

Correção: O CSS é uma **linguagem de estilos** (declarativa), e não uma linguagem de programação. Não possui controlo de fluxo algorítmico, lógica complexa ou manipulação direta de estruturas de dados.

Pergunta 3.1 1.0 valor
Explique o conceito de cliente-servidor aplicado a aplicações web.

Resposta Ideal:

O modelo cliente-servidor é uma arquitetura de computação distribuída em que o processamento é dividido entre:

  • Cliente (Frontend): O browser do utilizador que executa HTML/CSS/JS e a aplicação Angular. Inicia o contacto fazendo pedidos HTTP e trata da interação visual.
  • Servidor (Backend): A máquina remota que executa o Express/Node.js. Recebe pedidos, processa a lógica de negócio, interage com a base de dados (MongoDB) e devolve respostas.

A comunicação é feita via HTTP/HTTPS (Pedido-Resposta), mantendo dados e credenciais protegidos de forma segura no servidor.

Pergunta 3.3 1.0 valor
Explique o conceito de funções de middleware em ExpressJS.

Resposta Ideal:

No ExpressJS, middlewares são funções que se situam no meio do ciclo de pedido-resposta (Request-Response cycle) do servidor. Têm acesso ao objeto do pedido (req), da resposta (res) e à próxima função da pilha (next).

Os middlewares servem para executar código de auditoria (logs), modificar o request (ex: decifrar o utilizador a partir de um JWT), bloquear pedidos não autorizados ou passar o fluxo com next() para a rota seguinte.

Pergunta 3.7 1.5 valores
Recorde os conceitos Single Page Application (SPA) e Multiple Page Application (MPA). Defina e explique o que representam.

Diferenças SPA vs MPA:

  • SPA (Single Page Application): A aplicação carrega um único ficheiro index.html. O roteamento e troca de ecrãs são efetuados no client-side com JavaScript. Dados extra são pedidos em JSON à API. Não existem recarregamentos de página (reloads), tornando a experiência de utilização muito rápida e fluida. Ex: Angular.
  • MPA (Multiple Page Application): O modelo web tradicional. Qualquer navegação ou clique faz com que o browser envie um pedido HTTP e o servidor envie uma página HTML totalmente nova, forçando o recarregamento total. O processamento é no servidor (SSR). Ex: Express com EJS.
Pergunta 3.8 1.5 valores
Indique como gerir a autenticação e autorização de páginas em Angular. Teça considerações sobre a segurança da abordagem.

Abordagem de Autenticação/Autorização no Angular:

  • Guardar o token JWT no localStorage após o login.
  • Usar um HttpInterceptor para anexar automaticamente o token no header Authorization: Bearer <token> de todos os pedidos HTTP.

A segurança no frontend Angular é meramente visual. O código corre todo no browser e pode ser facilmente contornado ou alterado por um utilizador. Toda a autenticação e autorização deve ser obrigatoriamente enforcada e verificada pelo servidor no backend (Express), validando a assinatura do token em cada pedido API.

Explique o ciclo de vida de um componente Angular, focando nas funções e usos práticos de: ngOnInit, ngOnChanges e ngOnDestroy.
Solução Teórica Recomendada

1. `ngOnChanges()`: É o primeiro hook a ser executado. Corre sempre que propriedades de entrada vinculadas com @Input() mudam. Serve para atualizar dados dependentes no componente filho.

2. `ngOnInit()`: Executado uma única vez a seguir à inicialização das propriedades do componente. Usado de forma padrão para carregar dados de APIs/serviços e realizar lógicas de arranque.

3. `ngOnDestroy()`: Executado mesmo antes do Angular destruir o componente. Usado para efetuar operações de limpeza (cleanup) como fazer unsubscribe de Observables, parar timers ou libertar listeners de eventos para prevenir fugas de memória.

Crie um Schema Mongoose para um modelo Product contendo: Nome do produto (obrigatório, min 3 chars), Preço (obrigatório, min 0) e Categoria (limitada a "Eletrónica", "Moda" ou "Alimentação").
Código Schema Mongoose 
const productSchema = new mongoose.Schema({
    name: { 
        type: String, 
        required: [true, 'O nome é obrigatório.'], 
        minlength: [3, 'Mínimo de 3 caracteres.'] 
    },
    price: { 
        type: Number, 
        required: true, 
        min: [0, 'O preço deve ser superior ou igual a 0.'] 
    },
    category: { 
        type: String, 
        required: true,
        enum: ['Eletrónica', 'Moda', 'Alimentação']
    }
});
