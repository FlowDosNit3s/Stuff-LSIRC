01

Tipos Primitivos, Variáveis e Arrays

1.1 Tipos Primitivos

Java possui 8 tipos primitivos. Os tipos primitivos armazenam o valor diretamente na Stack de execução da JVM e não são considerados objetos:

byte (8 bits), short (16 bits), int (32 bits), long (64 bits), float (32 bits), double (64 bits), char (16 bits Unicode) e boolean (true/false).

Os valores por defeito dos tipos primitivos, quando declarados como atributos de instância de uma classe, são: 0 para numéricos inteiros, 0.0 para reais, '\u0000' para char e false para boolean. As variáveis locais declaradas no corpo dos métodos não possuem valores por defeito, obrigando o compilador a validar a sua inicialização obrigatória antes de qualquer utilização.

1.2 Constantes

As constantes em Java são declaradas recorrendo à palavra reservada final. Uma vez atribuído um valor à constante, este torna-se imutável e qualquer tentativa de reatribuição origina um erro em tempo de compilação. Por convenção de escrita, os identificadores de constantes são escritos integralmente em maiúsculas com underscores.

final double PI = 3.14159;
final int MAX_ELEMENTOS = 100;

1.3 Arrays

Os arrays em Java são estruturas de dados estáticas de dimensão fixa na memória que armazenam elementos do mesmo tipo de forma sequencial. O tamanho é definido obrigatoriamente na criação e não pode ser alterado posteriormente.

Os arrays de tipos primitivos são inicializados automaticamente com os valores padrão de cada tipo. Os arrays de referências de objetos são inicializados preenchendo todas as posições com a referência nula null.

int[] numeros = new int[5];         // Array de primitivos (tudo inicializado a 0)
String[] nomes = new String[3];     // Array de objetos (tudo inicializado a null)
int[] preDef = {1, 2, 3, 4, 5};    // Inicialização literal direta

Atenção: Para simular o redimensionamento de um array é necessário instanciar um novo array com a nova dimensão desejada e transferir manualmente os dados do array antigo para o novo bloco contíguo de memória Heap.

02

Classes e Objetos

2.1 Conceito de Classe

Uma classe atua como um molde ou especificação que define a estrutura de dados (atributos) e o comportamento operacional (métodos) que os objetos instanciados a partir dela vão partilhar.

public class Contentor {
    private String codigo;       // Atributo de instância (estado)
    private double capacidade;   // Atributo de instância (estado)

    public String getCodigo() {  // Método de instância (comportamento)
        return codigo;
    }
}

2.2 Criação de Objetos

Os objetos reais são criados através do operador new, que solicita à JVM a alocação de memória na Heap correspondente ao tamanho da classe e invoca o respetivo método construtor. A variável local que declara o tipo da classe armazena apenas um valor de referência contendo o endereço físico de memória da instância na Heap.

Contentor c = new Contentor();
// 'c' reside na Stack e armazena o endereço que aponta para o objeto na Heap

2.3 Variáveis de Instância vs Variáveis de Classe (static)

As variáveis de instância pertencem a cada objeto individualmente, existindo cópias separadas na memória Heap de cada objeto instanciado. As variáveis de classe, declaradas com o modificador static, pertencem à própria classe de forma global, existindo apenas uma única cópia alocada em memória partilhada por todas as instâncias.

public class Veiculo {
    private String matricula;            // Variável de instância
    private static int totalVeiculos = 0; // Variável de classe (partilhada)

    public Veiculo(String matricula) {
        this.matricula = matricula;
        totalVeiculos++;   // Modifica o estado partilhado global
    }

    public static int getTotalVeiculos() {  // Método estático
        return totalVeiculos;
    }
}

Regra: Métodos estáticos pertencem ao contexto da classe e não possuem contexto de instância. Logo, não podem aceder a atributos de instância não-estáticos nem utilizar as referências de controlo 'this' ou 'super'.

03

Construtores

3.1 Definição

Os construtores são blocos de código especiais encarregues de inicializar o estado de um objeto durante a instanciação com new. Apresentam as seguintes regras rígidas de sintaxe: devem possuir obrigatoriamente o mesmo nome exato da classe e não admitem qualquer tipo de retorno, nem mesmo a palavra-chave void.

3.2 Construtor por Defeito

Se nenhuma declaração de construtor for especificada pelo programador na escrita da classe, o compilador gera em tempo de compilação um construtor por defeito sem parâmetros. Este construtor invoca a inicialização da superclasse com `super()` e define o valor padrão para todos os campos. Se o programador escrever qualquer construtor parametrizado, o construtor automático por defeito deixa de ser gerado.

3.3 Encadeamento de Construtores

Podemos interligar múltiplos construtores dentro da mesma classe recorrendo ao método de chamada this(...) com argumentos, o que previne a repetição de lógica de inicialização de atributos. O aceso aos construtores da superclasse realiza-se através de super(...). Ambas as chamadas devem obrigatoriamente figurar como a primeira instrução no corpo do construtor e são mutuamente exclusivas.

public class AidBox {
    private String code;
    private String zone;

    public AidBox(String code) {
        this(code, "Desconhecida");    // Encaminha a inicialização
    }

    public AidBox(String code, String zone) {
        this.code = code;
        this.zone = zone;
    }
}
04

Encapsulamento e Modificadores de Acesso

4.1 Conceito de Encapsulamento

O encapsulamento visa a proteção da integridade dos dados internos de um objeto. O estado interno (atributos) deve ser blindado a acessos externos não validados declarando os campos como privados. O acesso ou mutação do estado realiza-se unicamente através de métodos públicos getters e setters que validam a consistência das operações.

4.2 Modificadores de Acesso

Java dispõe de quatro níveis de visibilidade controlada:

  • private: Acesso restrito estritamente a código definido dentro da própria classe.
  • protected: Acesso permitido no mesmo pacote de classes e a subclasses derivadas (mesmo localizadas em pacotes externos).
  • Sem modificador (package-private): Visibilidade restrita às classes contidas no mesmo pacote lógico.
  • public: Acesso livre a partir de qualquer classe em qualquer pacote da aplicação.

4.3 Getters e Setters com Validação

public class Container {
    private double capacidade;
    private double pesoAtual;

    public double getCapacidade() {
        return capacidade;
    }

    public void setPesoAtual(double peso) {
        // Validação defensiva do estado
        if (peso < 0 || peso > capacidade) {
            throw new IllegalArgumentException("Peso invalido.");
        }
        this.pesoAtual = peso;
    }
}
05

Enumerações (Enum)

As enumerações representam um tipo especial de classe Java concebida para gerir um conjunto fixo e fechado de constantes semânticas. Cada valor do enum constitui uma instância do tipo singleton. A comparação lógica de enums realiza-se de forma direta e segura através do operador relacional ==.

Os enums em Java suportam a declaração de atributos, construtores (obrigatoriamente privados) e métodos de instância ou estáticos.

public enum ItemType {
    PERISHABLE_FOOD("Alimentos Pereciveis"),
    NON_PERISHABLE_FOOD("Alimentos Nao Pereciveis"),
    CLOTHING("Vestuario"),
    MEDICINE("Medicamentos");

    private String descricao;

    ItemType(String descricao) { // Construtor implicitamente privado
        this.descricao = descricao;
    }

    public String getDescricao() {
        return descricao;
    }
}

Vantagens: Garante segurança de tipo (Type Safety) impedindo valores arbitrários inválidos em tempo de compilação, promove legibilidade e integração direta em blocos 'switch'.

06

Métodos e Sobrecarga

6.1 Definição de Métodos

Um método define o comportamento operacional da classe. É estruturado através da sua assinatura de método, que consiste na combinação do nome do método e da lista ordenada de parâmetros (tipos e quantidade). O tipo de retorno não faz parte da assinatura do método.

6.2 Sobrecarga de Métodos (Overloading)

A sobrecarga consiste na declaração de múltiplos métodos com o mesmo nome na mesma classe, desde que apresentem assinaturas distintas (diferente quantidade ou tipo de parâmetros). A seleção do método a executar realiza-se estritamente em tempo de compilação.

public int somar(int a, int b) { return a + b; }
public double somar(double a, double b) { return a + b; }
public int somar(int a, int b, int c) { return a + b + c; }
07

Passagem de Argumentos

Em Java, toda a passagem de argumentos para métodos é efetuada estritamente por valor. Não existe passagem por referência nativa no Java.

Para tipos primitivos, copia-se o valor direto na pilha local do método. Modificações na variável local do método não têm impacto na variável original do método chamador.

Para tipos de referência (objetos), é copiado o endereço físico de memória da referência. Como a variável local e a variável original possuem cópias do mesmo endereço de memória, ambas apontam para o mesmo objeto na Heap. Modificações no estado interno do objeto (atributos) são visíveis globalmente. Contudo, efetuar a reatribuição da referência local (ex: param = new Objeto()) altera apenas o endereço na Stack local, deixando a referência original intocada.

public static void alterarEstado(int[] arr) {
    arr[0] = 999;   // Afeta o array partilhado na Heap
}

public static void reatribuir(int[] arr) {
    arr = new int[]{1, 2, 3};   // Altera apenas o ponteiro da cópia na Stack local
}
08

Herança

8.1 Conceito

A herança apoia a reutilização de comportamento através da definição de hierarquias onde uma subclasse (especialização) estende membros públicos e protegidos de uma superclasse (generalização). Java suporta apenas a herança simples de classes recorrendo à palavra extends.

8.2 A Palavra Reservada super

No construtor, super(...) invoca a lógica de inicialização do pai e tem de ser invocado obrigatoriamente na primeira linha do bloco. No corpo dos métodos, a instrução super.metodo() executa a versão original do método da superclasse que foi sobreposto.

public class Veiculo {
    private String matricula;

    public Veiculo(String matricula) {
        this.matricula = matricula;
    }
}

public class Camiao extends Veiculo {
    private double cargaMax;

    public Camiao(String matricula, double cargaMax) {
        super(matricula); // Invocação do construtor pai
        this.cargaMax = cargaMax;
    }
}

8.3 Sobreposição de Métodos (Overriding)

A sobreposição ocorre quando um método da superclasse é redefinido na subclasse contendo a mesma assinatura e tipo de retorno incompatível. O compilador valida a redefinição sob a anotação @Override. A seleção do método a executar é dinâmica e decidida em tempo de execução pela JVM com base na classe da instância real na Heap.

09

Casting (Conversão de Tipos)

9.1 Upcasting

Conversão ascendente de uma referência de subclasse para superclasse. É uma operação automática (implícita) e perfeitamente segura. Implica a perda de visibilidade imediata de métodos exclusivos da subclasse, mantendo as invocações polimórficas.

Vehicle v = new RefrigeratedVehicleImpl("V-001", ...); // Upcasting implícito
v.getCode(); // Métodos comuns do contrato principal são válidos

9.2 Downcasting

Conversão descendente de uma referência genérica da superclasse para o tipo mais específico da subclasse. Requer um operador de coerção explícito e comporta perigos. Caso o objeto real na Heap não pertença à subclasse de destino, a JVM lança a exceção ClassCastException. É boa prática salvaguardar com instanceof.

if (v instanceof RefrigeratedVehicle) {
    RefrigeratedVehicle rv = (RefrigeratedVehicle) v; // Downcasting explícito seguro
    double km = rv.getMaxKilometers();
}
10

Classes Abstratas

Uma classe abstrata (delcarada com a palavra-chave abstract) destina-se a servir de base conceitual para subclasses, não podendo ser instanciada diretamente com new. Pode alojar métodos concretos com comportamento partilhado e métodos abstratos sem corpo que as subclasses concretas são obrigadas a sobrepor.

public abstract class Transporte {
    private String id;

    public Transporte(String id) {
        this.id = id;
    }

    public String getId() { return id; }
    public abstract double calcularCusto(double km); // Método abstrato (contrato)
}

O modificador final impede a extensão de classes, redefinição de métodos ou reatribuição de variáveis.

11

Interfaces

Uma interface serve para estabelecer um contrato puro de comportamento que qualquer classe pode assumir através de implements. Suporta a herança múltipla de tipo (uma classe implementa variadas interfaces). Todos os atributos declarados em interfaces são implicitamente constantes public static final.

public interface Vehicle {
    String getCode();
    ItemType getSupplyType();
}

A partir do Java 8, as interfaces toleram métodos concretos declarados como default (implementação padrão opcional) ou métodos static. O Java 9 adicionou suporte a métodos private para fins de reutilização de lógica interna.

12

Classes Abstratas vs Interfaces — Comparação Direta

Classes Abstratas: Estão integradas em hierarquias rígidas de herança simples. Têm a faculdade de reter e gerir variáveis de estado de instância mutáveis. Permitem a declaração de construtores de inicialização. Indicadas para relações "É UM".

Interfaces: Propiciam maior flexibilidade sob herança múltipla de tipo. São vedadas de armazenar variáveis de estado de instância, aceitando apenas constantes globais. Desprovidas de construtores. Indicadas para relações de comportamento do tipo "CONSEGUE FAZER".

13

Polimorfismo

13.1 Polimorfismo de Sobreposição (Dynamic Binding)

Ocorre em tempo de execução. O tipo formal da referência do objeto decide que métodos são permitidos ao compilar, mas no runtime a JVM executa a implementação da classe concreta baseada na instância real da Heap. Permite o tratamento uniforme de objetos de diferentes tipos sob uma mesma referência ancestral comum.

13.2 Polimorfismo de Sobrecarga (Static Binding)

Ocorre em tempo de compilação. A JVM seleciona o método específico a invocar com base estrita no tipo dos argumentos declarados na chamada.

14

Identidade vs Igualdade de Objetos

14.1 O Operador ==

Compara a igualdade binária nos primitivos e a igualdade referencial nos objetos (verifica se ambas as variáveis apontam para a mesma morada física de memória Heap).

14.2 O Método equals()

Destina-se a definir a igualdade semântica ou lógica com base em campos de dados. A implementação original na classe Object limita-se a usar ==, obrigando à sua sobreposição nas classes de negócio.

14.3 A Estrutura de equals Padrão

@Override
public boolean equals(Object obj) {
    if (this == obj) return true;                      // 1. Identidade
    if (obj == null) return false;                     // 2. Nulo
    if (!(obj instanceof Vehicle)) return false;       // 3. Compatibilidade de Tipo
    Vehicle other = (Vehicle) obj;                     // 4. Cast seguro
    return this.code.equals(other.getCode());          // 5. Lógica de campos
}

14.4 instanceof vs getClass()

O operador instanceof aceita correspondências em subclasses descendentes da hierarquia e implementações de interfaces (visão polimórfica flexível). A instrução getClass() == obj.getClass() valida estritamente a mesma classe exata, excluindo classes derivadas (garantia rígida de simetria do contrato equals).

15

Exceções

15.1 Hierarquia

Toda a estrutura deriva de Throwable, ramificando em Error (situações catastróficas da máquina virtual irrecuperáveis) e Exception (anomalias de fluxo lógico controláveis).

15.2 Checked vs Unchecked

As exceções verificadas (checked) são subclasses de Exception (com exceção das descendentes de RuntimeException). O compilador obriga a tratá-las explicitamente com try-catch ou a delegar o aviso na assinatura do método com a cláusula throws.

As exceções não verificadas (unchecked) herdam de RuntimeException. O compilador dispensa a verificação obrigatória, indicando habitualmente falhas ou inconsistências de desenvolvimento de código (ex: NullPointerException).

15.3 Mecanismo try-catch-finally

try {
    route.addAidBox(aidBox);
} catch (RouteException e) {
    System.out.println(e.getMessage()); // Captura de erro
} finally {
    System.out.println("Executa sempre."); // Execução final garantida para fecho de recursos
}
16

Composição vs Herança

A herança constitui uma ligação forte e estática baseada em relações "É UM", herdando a totalidade de membros da superclasse de forma direta. A composição propõe uma dependência fraca e dinâmica onde uma classe integra instâncias de outros objetos na sua declaração de atributos, estabelecendo relações do tipo "TEM UM".

A composição é comummente preferida à herança para reduzir o acoplamento sistémico entre classes, flexibilizar a substituição dinâmica de comportamentos em tempo de execução e contornar problemas de fragilidade inerentes à herança (onde mudanças na classe base afetam inesperadamente o funcionamento das subclasses).

17

Membros Estáticos (static)

Atributos e métodos estáticos pertencem conceptualmente ao escopo da classe, desvinculados de qualquer instância individual. Existe uma única alocação física do campo na memória JVM, que é partilhada por todas as instâncias da classe. Métodos estáticos podem ser chamados diretamente a partir do identificador da classe, estando impedidos de referenciar this ou interagir com campos de instância não-estáticos.

18

A Palavra-Chave final

O modificador final confere propriedades de imutabilidade consoante o seu contexto de aplicação:

  • Em variáveis: Estabelece constantes, impedindo a reatribuição de valores a campos primitivos ou reatribuição de moradas de memória a referências.
  • Em métodos: Proíbe expressamente a sua sobreposição pelas subclasses na hierarquia.
  • Em classes: Trunca a herança, impedindo a criação de quaisquer subclasses a partir da classe final.

Palavras Reservadas Essenciais

Glossário de termos fundamentais da linguagem:

class (define classe), new (instancia na Heap), this (auto-referência), super (referência à superclasse), extends (herança simples), implements (implementa interface), abstract (declaração abstrata), interface (contrato), static (membro de classe), final (imutável), private/protected/public (acessos), void (sem retorno), throw (lança exceção), throws (indica exceção), try/catch/finally (gestão de erros), instanceof (verifica tipo) e enum (conjunto de constantes).

20

Padrões de Código Frequentes em Exame

20.1 Implementação de Interface com Estado e equals

public class XImpl implements X {
    private String code;
    private TipoEstado state;

    public XImpl(String code) {
        this.code = code;
        this.state = TipoEstado.VALOR_DEFEITO;
    }

    @Override
    public String getCode() { return this.code; }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null) return false;
        if (!(obj instanceof X)) return false;
        X other = (X) obj;
        if (this.code == null) {
            return other.getCode() == null;
        }
        return this.code.equals(other.getCode());
    }

    @Override
    public String toString() {
        return "X [" + code + " | " + state + "]";
    }
}

20.2 Gestão de Arrays Estáticos (Adicionar e Remover)

private Elemento[] elementos;
private int count;

public void add(Elemento e) throws MinhaExcecao {
    if (e == null) throw new MinhaExcecao("Nulo.");
    if (count >= elementos.length) throw new MinhaExcecao("Cheio.");
    for (int i = 0; i < count; i++) {
        if (elementos[i].equals(e)) throw new MinhaExcecao("Duplicado.");
    }
    elementos[count] = e;
    count++;
}

public Elemento remove(Elemento e) throws MinhaExcecao {
    for (int i = 0; i < count; i++) {
        if (elementos[i].equals(e)) {
            Elemento removed = elementos[i];
            for (int j = i; j < count - 1; j++) {
                elementos[j] = elementos[j + 1];
            }
            elementos[count - 1] = null;
            count--;
            return removed;
        }
    }
    throw new MinhaExcecao("Nao encontrado.");
}

20.3 Redimensionamento sem Nulos (Shrinking)

public Elemento[] getElementos() {
    Elemento[] result = new Elemento[count];
    for (int i = 0; i < count; i++) {
        result[i] = elementos[i];
    }
    return result;
}

20.4 Iteração, Filtragem e Cópia de Dados

Elemento[] temp = new Elemento[total.length];
int filteredCount = 0;
for (int i = 0; i < total.length; i++) {
    if (total[i] != null && condicao(total[i])) {
        temp[filteredCount] = total[i];
        filteredCount++;
    }
}
Elemento[] result = new Elemento[filteredCount];
for (int i = 0; i < filteredCount; i++) {
    result[i] = temp[i];
}
return result;
