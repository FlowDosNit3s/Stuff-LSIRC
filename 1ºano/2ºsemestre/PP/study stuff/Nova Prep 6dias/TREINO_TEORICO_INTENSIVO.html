1. Encapsulamento & Modificadores de Acesso

Justifique por que razão o acesso direto aos atributos de uma classe é considerado uma má prática e ilustre o uso correto com um exemplo prático. 🔥 95% Prob.

✍️ Resposta Tipo de Exame (Essencial)

  • Conceito de Encapsulamento: Ocultação do estado interno de uma classe, permitindo acesso e modificação apenas através de métodos controlados (getters/setters).
  • Modificadores de Acesso: private (apenas na própria classe), default (mesmo pacote), protected (pacote e subclasses), public (acesso universal).

💻 Excerto de Código Java (Simples & Tema Unificado)

    public void setCapacidade(double c) {
        if (c <= 0) {
            throw new IllegalArgumentException("Capacidade invalida.");
        }
        this.capacidade = c; // Validação defensiva
    }
}

✍️ Resposta Tipo de Exame (Essencial)

    public Camiao(String matricula) {
        this(matricula, 1000.0); // Encadeamento: chama o outro construtor de Camiao

3. Variáveis de Classe (static) vs Variáveis de Instância

Esclareça as razões pelas quais a utilização da palavra reservada this não é permitida no corpo de métodos declarados como estáticos e ilustre a sua resposta com um exemplo estruturado. ⚡ 85% Prob.

✍️ Resposta Tipo de Exame (Essencial)

  • Instância vs Classe (static): Atributos de instância pertencem a cada objeto na Heap (uma cópia por objeto). Atributos static pertencem à classe (uma única cópia partilhada por todas as instâncias).
  • Proibição de this em Estáticos: O operador this aponta para a instância atual na Heap. Métodos estáticos pertencem à classe e correm sem qualquer objeto instanciado, logo this não existe (causa erro de compilação).

    private static int totalCamioes = 0; // Atributo de Classe (Partilhado)

    public static int getTotalCamioes() {
        // return this.matricula; -> ERRO DE COMPILAÇÃO! Não há "this" em contexto estático.
        return totalCamioes; // OK
    }
}

5. Memória (Stack/Heap), GC e NullPointerException

✍️ Resposta Tipo de Exame (Essencial)

    // c1.getMatricula(); -> LANÇA NullPointerException (referência é null)!
}

        // System.out.println(velocidade); -> ERRO DE COMPILAÇÃO!

7. O Operador `this` e os seus 3 Usos Principais
Explique a finalidade da palavra reservada this em Java. Identifique e exemplifique os três contextos de utilização principais deste operador no desenvolvimento de classes. ⚡ 80% Prob.

✍️ Resposta Tipo de Exame (Essencial)

  • Conceito: Referência implícita ao próprio objeto em execução na Heap.
  • 3 Usos Principais:
    1. Desambiguação de Escopo: Distinguir atributo de instância de parâmetro (this.capacidade = capacidade).
    2. Encadeamento de Construtores: Chamar outro construtor da própria classe (this(100.0)).
    3. Passagem da Própria Instância: Enviar a própria referência como argumento (frota.adicionar(this)).

💻 Excerto de Código Java (Simples & Tema Unificado)

public class Contentor {
    private double capacidade;

    public Contentor(double capacidade) {
        this.capacidade = capacidade; // 1. Desambiguação de escopo
    }

    public Contentor() {
        this(100.0); // 2. Encadeamento de construtor
    }

    public void registar(Gestor g) {
        g.adicionarContentor(this); // 3. Passagem da própria referência
    }
}

10. Polimorfismo: Overloading vs Overriding

15. O Contrato Sagrado entre `equals()` e `hashCode()`
Explique o contrato estabelecido entre os métodos equals() e hashCode() em Java. Descreva em pormenor o comportamento anómalo que ocorre ao utilizar coleções baseadas em tabelas de dispersão (como HashSet ou HashMap) quando `equals()` é redefinido mas `hashCode()` não. ⚡ 85% Prob.

✍️ Resposta Tipo de Exame (Essencial)

  • Contrato Especificado: Se a.equals(b) é true, obrigatoriamente a.hashCode() == b.hashCode().
  • Problema em Tabelas Hash: Coleções de hash calculam a posição com hashCode(). Se equals() for redefinido sem hashCode(), objetos iguais geram hashes diferentes e ficam em posições distintas (método de busca falha e aceita duplicados).

💻 Excerto de Código Java (Simples & Tema Unificado)

public class Camiao {
    private String matricula;

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || !(obj instanceof Camiao)) return false;
        Camiao other = (Camiao) obj;
        return this.matricula != null && this.matricula.equals(other.matricula);
    }

    @Override
    public int hashCode() {
        return (this.matricula == null) ? 0 : this.matricula.hashCode();
    }
}

23. Passagem de Argumentos: Primitivos vs Referências de Objetos

✍️ Resposta Tipo de Exame (Essencial)

  • Regra Fundamental: Em Java, toda a passagem de argumentos é estritamente Por Valor (pass-by-value).
  • Primitivos: Copia-se o valor numérico para a Stack. Alterações não afetam a variável do chamador.
  • Referências a Objetos: Copia-se a referência (endereço na Heap). Reatribuir a variável com new não altera o chamador, mas chamar métodos mutadores altera o objeto partilhado na Heap.

💻 Excerto de Código Java (Simples & Tema Unificado)

public static void modificar(Camiao c, int peso) {
    peso = 999; // Cópia do primitivo: NÃO altera a variável original
    c.setCapacidade(500.0); // Alteração no objeto na Heap: VISÍVEL fora!
    c = new Camiao("XX-99-99"); // Reatribuição local: NÃO afeta o chamador
}

25. Gestão Manual de Arrays Nativos vs Coleções e Complexidade de Cópia
Nos exames de PP da ESTG, é estritamente exigida a utilização de arrays nativos com controlo de contador em vez de coleções dinâmicas (como ArrayList). Explique as implicações algorítmicas de gestão de memória, verificação de nulos e o custo de cópia de referências ao expandir ou compactar arrays. ⚡ 85% Prob.

✍️ Resposta Tipo de Exame (Essencial)

  • Exigência nos Exames PP: Testar o domínio manual de alocação de memória, controlo de limites, verificação de nulos e gestão de contadores (count) sem abstrações de ArrayList.
  • Posições Nulas vs Contador: Num array nativo de capacidade $N$ com $K$ elementos preenchidos, as posições restantes contêm null. Iterar exige percorrer estritamente até i < count ou validar if (arr[i] != null).
  • Compactação (Complexidade $O(N)$): Alocar um novo array com tamanho exatamente igual a count e copiar elemento a elemento via ciclo for standard.

💻 Excerto de Código Java (Simples & Tema Unificado)

public Camiao[] compactarFrota(Camiao[] temp, int count) {
    Camiao[] resultado = new Camiao[count]; // Tamanho exato sem posições nulas
    for (int i = 0; i < count; i++) { // Ciclo for standard (sem foreach)
        resultado[i] = temp[i];
    }
    return resultado;
}
