1. Encapsulamento & Modificadores de Acesso
Explique detalhadamente o conceito de encapsulamento em Programação Orientada a Objetos. Descreva como os modificadores de acesso (private, protected, default, public) contribuem para este princípio. Justifique por que razão o acesso direto aos atributos de uma classe é considerado uma má prática e ilustre o uso correto com um exemplo prático. 🔥 95% Prob.
  • O Essencial: Encapsulamento é a ocultação da estrutura interna de um objeto. O estado (atributos) não deve ser acedido diretamente, mas sim manipulado através de métodos controlados (getters/setters).
  • Modificadores: private (só na classe), default (só no pacote), protected (pacote + subclasses), public (em todo o lado).
  • Porquê não public? Porque quebra o encapsulamento. Código externo poderia injetar valores inválidos (ex: capacidade negativa), violando as regras de negócio e acoplando o cliente à representação interna.

public class Contentor {

    public void setCapacidade(double c) {
        if (c <= 0) throw new IllegalArgumentException("Capacidade inválida.");
        this.capacidade = c; // Acesso validado defensivamente
    }
}

2. Construtores: invocação com `this()` e `super()`
Discuta a finalidade dos construtores na instanciação de objetos em Java. Explique o conceito de sobrecarga de construtores e demonstre como o encadeamento de construtores pode ser alcançado através das palavras reservadas this() e super(). Esclareça as restrições sintáticas associadas à utilização destas invocações. ⚡ 85% Prob.
  • O Essencial: Construtores inicializam o estado de um objeto na Heap. Se nenhum for escrito, o compilador gera o default constructor vazio sem argumentos.
  • Sobrecarga e Encadeamento: Podemos ter múltiplos construtores (com parâmetros diferentes). this() chama outro construtor da própria classe. super() chama o construtor da superclasse.
  • Restrição Sintática Crítica: As invocações a this() ou super() têm de ser obrigatoriamente a primeira linha de código dentro do construtor, e nunca podem ser usadas em simultâneo no mesmo construtor.

💻 Exemplo Prático

    public Veiculo(String mat) { /* inicializa matrícula */ }
}

    private double tara;
    
    public Camiao(String mat, double tara) {
        super(mat); // Obrigatório ser a 1ª linha (chama superclasse)
        this.tara = tara;
    }
    
    public Camiao(String mat) {
        this(mat, 1000.0); // Encadeamento: chama o outro construtor de Camiao
    }
}

5. Memória (Stack/Heap), GC e NullPointerException

6. Inicialização de Atributos de Instância vs Variáveis Locais
Distinga o comportamento da JVM e do compilador relativamente à inicialização por defeito de atributos de instância em contrapartida com variáveis locais declaradas no corpo de métodos. Explique a razão técnica por trás dessa distinção. ⚡ 75% Prob.
  • Atributos de Instância (Campos de Classe): Quando um objeto é alocado na Heap com new, a JVM inicializa automaticamente todos os seus atributos com valores por defeito: 0 para inteiros, 0.0 para reais, false para booleanos e null para referências.
  • Variáveis Locais: Alocadas na Stack durante a execução de um método. A JVM NÃO as inicializa por defeito. O compilador Java exige estritamente que uma variável local seja explicitamente inicializada antes de qualquer leitura. Caso contrário, gera um erro de compilação ("variable might not have been initialized").
  • Razão Técnica: A inicialização automática na Heap garante a integridade do estado dos objetos. Na Stack, a ausência de inicialização automática evita overhead de desempenho na execução de chamadas frequentes a métodos.

💻 Exemplo Prático

    private int atributoInstancia; // Inicializado automaticamente a 0

    public void testar() {
        int varLocal; // Sem valor por defeito
        System.out.println(this.atributoInstancia); // Imprime 0 sem erros
        // System.out.println(varLocal); -> ERRO DE COMPILAÇÃO!
    }
}

7. O Operador `this` e os seus 3 Usos Principais
Explique a finalidade da palavra reservada this em Java. Identifique e exemplifique os três contextos de utilização principais deste operador no desenvolvimento de classes. ⚡ 80% Prob.
  • Conceito: this é uma variável de referência implícita que aponta para o próprio objeto em execução na memória Heap.
  • 3 Usos Principais:
    1. Desambiguação de Escopo: Diferenciar atributos de instância de parâmetros de métodos com o mesmo nome (this.codigo = codigo).
    2. Encadeamento de Construtores: Invocar outro construtor da própria classe (this(codigo, 50.0)), devendo ser a 1ª linha do construtor.
    3. Passagem da Própria Instância: Passar o próprio objeto como argumento para outros métodos ou construtores externos (registarNoPainel(this)).

💻 Exemplo Prático

public class AidBoxImpl {
    private String code;
    private double capacity;

    public AidBoxImpl(String code, double capacity) {
        this.code = code; // 1. Desambiguação de escopo
        this.capacity = capacity;
    }

    public AidBoxImpl(String code) {
        this(code, 100.0); // 2. Encadeamento de construtor
    }

    public void registar(Gestor g) {
        g.adicionarCaixa(this); // 3. Passagem da própria referência
    }
}

15. O Contrato Sagrado entre `equals()` e `hashCode()`
Explique o contrato estabelecido entre os métodos equals() e hashCode() em Java. Descreva em pormenor o comportamento anómalo que ocorre ao utilizar coleções baseadas em tabelas de dispersão (como HashSet ou HashMap) quando `equals()` é redefinido mas `hashCode()` não. ⚡ 85% Prob.
  • O Contrato Especificado:
    1. Se a.equals(b) devolve true, então a.hashCode() DEVE ser estritamente igual a b.hashCode().
    2. Se dois objetos têm o mesmo hashCode(), não é obrigatório que sejam iguais (pode ocorrer colisão Hash).
  • Consequência de Negligenciar `hashCode()`: Estruturas como HashSet usam o hashCode() para calcular o índice do balde (bucket) de memória. Se hashCode() não for redefinido, dois objetos logicamente iguais terão hashes diferentes e serão guardados em posições distintas. Resultado: o método contains() falhará e a coleção aceitará duplicados lógicos!

💻 Exemplo Prático

public class AidBoxImpl {
    private String code;

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || !(obj instanceof AidBoxImpl)) return false;
        AidBoxImpl other = (AidBoxImpl) obj;
        return this.code != null && this.code.equals(other.code);
    }

    @Override
    public int hashCode() {
        return (this.code == null) ? 0 : this.code.hashCode(); // Paridade obrigatória!
    }
}

21. I/O em Java: Byte Streams vs Character Streams

  • Byte Streams (`InputStream` / `OutputStream`): Processam dados em unidades de 8 bits (bytes puros). Adequados para dados binários não estruturados como imagens, áudio, ficheiros executáveis ou streams serializados.

// Byte Stream (8 bits binário)
try (java.io.FileInputStream fis = new java.io.FileInputStream("foto.png")) { fis.read(); }

// Character Stream (16 bits Unicode texto)
try (java.io.FileReader fr = new java.io.FileReader("resumo.txt")) { fr.read(); }

25. Gestão Manual de Arrays Nativos vs Coleções e Complexidade de Cópia
Nos exames de PP da ESTG, é estritamente exigida a utilização de arrays nativos com controlo de contador em vez de coleções dinâmicas (como ArrayList). Explique as implicações algorítmicas de gestão de memória, verificação de nulos e o custo de cópia de referências ao expandir ou compactar arrays. ⚡ 85% Prob.
  • Porquê Arrays Nativos no Exame? Para avaliar a capacidade do aluno em gerir manualmente alocação de memória, validação de limites de arrays, manipulação de índices de contagem (`count`) e prevenção rigorosa de `NullPointerException`.
  • Gestão de Contadores & Nulos: Um array nativo alocado com tamanho 10 que apenas contém 3 elementos concretos tem as restantes 7 posições com `null`. Iterações devem obrigatoriamente validar `if (arr[i] != null)` ou iterar estritamente até `i < count`.
  • Complexidade de Cópia: Ao devolver um array de resultados compactado (sem buracos nulos), é necessário instanciar um array exatamente de tamanho `count` e copiar elemento a elemento (Complexidade O(N) em tempo e espaço).

💻 Exemplo Prático (Compactação de Array)

public Route[] compactarRotas(Route[] temp, int count) {
    Route[] result = new Route[count]; // Tamanho exato sem nulos!
    for (int i = 0; i < count; i++) {
        result[i] = temp[i]; // Cópia direta da referência
    }
    return result;
}
