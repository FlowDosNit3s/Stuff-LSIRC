3.1 Conceitos de POO, Classe, Objeto e Instanciação

  • POO: Modelo baseado na abstração do mundo real em entidades com estado (atributos) e comportamento (métodos).
  • Classe: Molde abstrato que define a estrutura de dados e comportamento de um tipo de objeto.
  • Objeto / Instância: Entidade concreta alocada na Heap criada com new.
AidBox box = new AidBoxImpl("AB01", "Norte"); // Instanciação na Heap

3.4 Membros Estáticos (static)

  • Pertencem à classe, não às instâncias. Uma cópia partilhada por todos os objetos.
  • Restrições: Métodos estáticos NÃO acedem a atributos de instância nem usam this/super.

3.5 O Modificador final

  • Variável: Constante. Primitivo: valor inalterável. Objeto: referência inalterável mas estado interno pode mudar.
  • Método: Impede overriding nas subclasses.
  • Classe: Impede herança (ex: String).

3.6 Identidade (==) vs Igualdade (equals())

  • == compara endereços de memória na Heap (identidade física).
  • equals() compara conteúdo lógico. Redefinir obriga a redefinir hashCode().
@Override public boolean equals(Object obj) {
    if (this == obj) return true;
    if (obj == null || !(obj instanceof AidBox)) return false;
    AidBox other = (AidBox) obj;
    return this.code != null && this.code.equals(other.getCode());
}

3.7 Passagem de Argumentos (Pass-by-Value)

  • Primitivos: Copia-se o valor. Alterações no método NÃO afetam a variável original.
  • Objetos: Copia-se o endereço. Reatribuir NÃO afeta. Chamar métodos mutadores ALTERA o objeto na Heap.

3.8 Herança e super

Subclasse herda atributos e métodos. super() no construtor invoca o construtor pai. super.metodo() acede ao método sobreposto da superclasse.

3.10 Casting e instanceof

  • Upcasting: Para superclasse (automático, seguro).
  • Downcasting: Para subclasse (explícito). Risco de ClassCastException. Usar instanceof.
if (v instanceof RefrigeratedVehicle) {
    RefrigeratedVehicle rv = (RefrigeratedVehicle) v; // Downcasting seguro
}

3.11 Composição vs Herança

  • Herança ("É UM"): Acoplamento forte. Superclasse frágil.
  • Composição ("TEM UM"): Encapsulamento preservado. Acoplamento fraco. Recomendada.

  • Unchecked: Compilador NÃO exige. Ex: NullPointerException, IllegalArgumentException.
  • finally: Executa SEMPRE (mesmo com return no try).

3.13 Tipos Enumerados (enum)

  • Constantes = instâncias únicas (singletons) imutáveis.
  • Construtores OBRIGATORIAMENTE private.
public enum ItemType {
    PERISHABLE_FOOD("Perecível"), MEDICINE("Medicamentos");
    private final String desc;
    private ItemType(String desc) { this.desc = desc; }
}

3.14 Classes Wrapper, Autoboxing e Unboxing

  • Wrappers: int → Integer, double → Double.
  • Risco: == compara endereços na Heap. Falha fora da cache Integer (-128 a 127). Usar SEMPRE .equals().

3.15 I/O: Byte Streams vs Character Streams

  • Byte Streams (InputStream/OutputStream): 8 bits. Dados binários (imagens, áudio, zip).
  • Character Streams (Reader/Writer): 16 bits Unicode. Texto legível (.txt, .json).

3.16 Serialização (Serializable, transient, serialVersionUID)

  • Converte estado do objeto em bytes. Exige java.io.Serializable.
  • transient: atributos NÃO serializados (ex: passwords).
  • serialVersionUID: valida compatibilidade de versões na deserialização.

public class AidBoxFullException extends Exception {

}

public class AidBoxImpl implements AidBox {
    private String code, zone;
    private Container[] containers;
    private int numberOfContainers;
    private static final int MAX = 4;

    public AidBoxImpl(String code, String zone) {
        if (code == null || zone == null) throw new IllegalArgumentException("Nulos.");
        this.code = code; this.zone = zone;
        this.containers = new Container[MAX]; this.numberOfContainers = 0;
    }
    @Override public String getCode() { return this.code; }
    @Override public String getZone() { return this.zone; }
    @Override public Container[] getContainers() {
        Container[] r = new Container[this.numberOfContainers];
        for (int i = 0; i < this.numberOfContainers; i++) r[i] = this.containers[i];
        return r;
    }
    public boolean addContainer(Container c) throws AidBoxFullException {
        if (c == null) throw new IllegalArgumentException("Nulo.");
        if (this.numberOfContainers >= MAX) throw new AidBoxFullException("Cheia!");
        this.containers[this.numberOfContainers++] = c; return true;
    }
    @Override public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || !(obj instanceof AidBox)) return false;
        return this.code.equals(((AidBox)obj).getCode());
    }
}

public class ReportImpl implements Report {
    public int countContainersByType(AidBox box, ItemType type) {
        if (box == null || type == null || box.getContainers() == null) return 0;
        int count = 0;
        for (Container c : box.getContainers()) if (c != null && c.getType() == type) count++;
        return count;
    }
    public double getAverageOccupancy(AidBox box) {
        if (box == null || box.getContainers() == null) return 0.0;
        double sum = 0; int valid = 0;
        for (Container c : box.getContainers()) {
            if (c != null && c.getCapacity() > 0) {
                Measurement last = c.getLastMeasurement();
                if (last != null) { sum += (last.getValue() / c.getCapacity()) * 100; valid++; }
            }
        }
        return valid == 0 ? 0.0 : sum / valid;
    }
    @Override public String generate(IInstitution inst) {
        if (inst == null || inst.getAidBoxes() == null) return "";
        StringBuilder sb = new StringBuilder();
        for (AidBox box : inst.getAidBoxes()) {
            if (box != null && getAverageOccupancy(box) > 50.0) {
                sb.append("AidBox: ").append(box.getCode()).append(" | Zona: ").append(box.getZone()).append("\n");
            }
        }
        return sb.toString();
    }
}

1. Diferenças Fundamentais:

  • Herança: Uma classe só pode estender uma classe abstrata (extends), mas pode implementar múltiplas interfaces (implements).
  • Estado: Classes abstratas podem possuir atributos de instância mutáveis com qualquer modificador (private, protected), enquanto interfaces possuem apenas constantes públicas estáticas imutáveis (public static final).
  • Construtores: Classes abstratas possuem construtores invocados por subclasses via super(). Interfaces não possuem construtores.
  • Métodos: Classes abstratas contêm métodos abstratos e concretos. Interfaces contêm métodos abstratos, métodos default (com implementação padrão) e métodos static.

2. Critério de Escolha: Opta-se por uma classe abstrata quando existe uma relação de herança "É UM" (IS-A) com partilha de código e estado entre classes fortemente relacionadas (ex: classe base Vehicle). Opta-se por uma interface para definir um contrato de comportamento "É CAPAZ DE" entre classes dispares e não relacionadas (ex: RouteValidator).

🔑 Clique para ver a Resolução Teórica 2

1. Mecanismo Pass-by-Value: Em Java, a passagem de argumentos é estritamente realizada por valor (pass-by-value).

2. Comportamento para Primitivos vs Objetos:

  • Tipos Primitivos (int, double, boolean): O valor binário é copiado para uma variável local do método. Alterações no parâmetro dentro do método afetam apenas a cópia local, mantendo a variável original inalterada.
  • Tipos de Referência (Objetos): O valor copiado para o parâmetro local é o endereço de memória de referência do objeto na Heap.

3. Esclarecimento do Equívoco Frequente: Reatribuir o ponteiro de referência dentro do método (ex: c = new ContainerImpl(...)) afeta apenas a cópia local do ponteiro e NÃO reatribui a variável original fora do método. Contudo, chamar métodos mutadores através da referência (ex: c.setCapacity(500)) altera o estado interno do objeto partilhado na Heap, sendo essa alteração visível globalmente.

Exemplo Prático de Código Java:

    x = 99;              // Não afeta o int original fora do método
    c.setCapacity(500);  // ALTERA o objeto real na Heap visível fora do método!
}

1. Identidade vs Igualdade:

  • O operador == compara a **identidade física** de referências de memória na Heap. Devolve `true` apenas se ambas as variáveis apontarem para o mesmo endereço exato.

public class AlertManagerImpl implements AlertManager {
    public boolean isContainerInCriticalState(Container c) {
        if (c == null) return true;
        Measurement last = c.getLastMeasurement();
        if (last == null) return true;
        if (c.getCapacity() <= 0) return true;
        return (last.getValue() / c.getCapacity()) * 100 > 95.0;
    }

    public int countCriticalContainersInAidBox(AidBox box) {
        if (box == null) return 0;
        Container[] cs = box.getContainers();
        if (cs == null) return 0;
        int count = 0;
        for (int i = 0; i < cs.length; i++)
            if (isContainerInCriticalState(cs[i])) count++;
        return count;
    }

    @Override public Alert[] generateMaintenanceAlerts(IInstitution inst) {
        if (inst == null) return new Alert[0];
        AidBox[] boxes = inst.getAidBoxes();
        if (boxes == null) return new Alert[0];

        int totalAlertas = 0;
        for (int i = 0; i < boxes.length; i++)
            if (boxes[i] != null && countCriticalContainersInAidBox(boxes[i]) > 0)
                totalAlertas++;

        if (totalAlertas == 0) return new Alert[0];

        Alert[] result = new Alert[totalAlertas];
        int idx = 0;
        for (int i = 0; i < boxes.length; i++) {
            if (boxes[i] != null) {
                int numCriticos = countCriticalContainersInAidBox(boxes[i]);
                if (numCriticos > 0) {
                    String codigoAlerta = "ALT-" + boxes[i].getCode();
                    String descricao = "AidBox com " + numCriticos + " contentor(es) critico(s).";
                    int gravidade = Math.min(numCriticos, 5);
                    result[idx++] = new AlertImpl(codigoAlerta, AlertType.CAPACITY_OVERFLOW, descricao, gravidade);
                }
            }
        }
        return result;
    }
